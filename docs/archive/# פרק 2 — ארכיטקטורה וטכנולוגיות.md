## 2.2 דפוס ארכיטקטורי

המערכת בנויה בדפוס **MVC מורחב** (Model-View-Controller) בשכבות:

| שכבה | אחריות | תיקייה |
|------|--------|--------|
| **Routes** | הגדרת נקודות קצה (endpoints) ושיוך ל-controllers | `backend/routes/` |
| **Middleware** | אימות JWT, ולידציה, טיפול שגיאות, rate limiting | `backend/middleware/` |
| **Controllers** | לוגיקת הבקשה — קבלת נתונים, קריאה ל-services | `backend/controllers/` |
| **Services** | לוגיקה עסקית, קריאה ל-APIs חיצוניים | `backend/services/` |
| **Models** | הגדרת סכמות Mongoose ואינטראקציה עם MongoDB | `backend/models/` |
| **Validators** | ולידציה של קלט (Joi) | `backend/validators/` |

## 2.4 זרימת בקשה טיפוסית

```
1. משתמש לוחץ "הוסף עסקה" ב-Frontend
2. React → POST /api/transactions עם JWT ב-header
3. authMiddleware מאמת את הטוקן
4. transactionValidator מוודא את הקלט
5. transactionController.create מקבל את הבקשה
6. transactionService.create יוצר מסמך ב-MongoDB
7. budgetService.checkAlert בודק חריגת תקציב
8. אם חריגה → emailService.sendAlert שולח מייל
9. תגובה חוזרת ל-Frontend → עדכון UI
```
